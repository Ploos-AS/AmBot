# M4 — ARexx Command API

M4 exposes AmBot as a classic Amiga ARexx host through the public message port `AMBOT`.

## Runtime model

AmBot opens `rexxsyslib.library`, publishes the `AMBOT` Exec message port and services ARexx requests throughout the IRC session lifecycle. The socket loop uses `WaitSelect()` so IRC traffic and ARexx messages can wake the same runtime loop.

The ARexx host remains available while AmBot is disconnected or waiting to reconnect. This makes `STATUS`, `CONNECT`, `DISCONNECT` and `QUIT` useful as lifecycle controls, not only while an IRC socket is active.

## Commands

- `STATUS`
- `CONNECT`
- `DISCONNECT`
- `JOIN channel [key]`
- `PART channel [reason]`
- `MSG target text`
- `NOTICE target text`
- `ACTION target text`
- `WHOIS nick`
- `MODE target modes...`
- `TOPIC channel [text]`
- `RAW irc-line`
- `RELOAD`
- `QUIT`

`RELOAD` is reserved now but returns RC 5 until the configuration milestone adds a reloadable configuration source.

## Result contract

ARexx return code is placed in `RC`/`rm_Result1`. When the caller requests a result string, AmBot returns a short status string through `rm_Result2`.

General convention:

- `0` — success
- `5` — command recognized but deferred/not currently available
- `10` — caller/argument/state error
- `20` — runtime/send failure

## Shared operations

Network-affecting ARexx commands call the same control/IRC operations used by the native runtime. This keeps ARexx as a first-class control API rather than a parallel implementation.

## Qualification boundary

M4 is implemented in source and covered by `make check`. Native build and live ARexx qualification still need Bebbo/FS-UAE or real AmigaOS runtime testing before the milestone is marked runtime-qualified.
