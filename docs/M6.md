# M6 — Persistence and Modules

M6 adds a bounded persistent configuration layer and module discovery without raising the AmigaOS 2.04+/68000 baseline.

## Configuration

An optional config file may be supplied as the final CLI argument:

```text
AmBot HOST PORT NICK [USER] [PASS] [OWNER] [CONFIG]
```

Supported keys are `HOST`, `PORT`, `NICK`, `USER`, `PASS`, `OWNER`, `HOOK_DIR`, `MODULE_DIR`, and repeated `CHANNEL` entries. CLI values act as defaults and the config file overrides them.

Up to 16 channels are retained in memory. They are joined automatically after IRC registration.

## ARexx RELOAD

`RELOAD` is now active. It requests the current config file to be read again and rediscovers modules. If no config file is active, AmBot reports that reload cannot be completed.

Connection identity changes such as HOST, PORT or NICK naturally take full effect on the next connection cycle. Hook and module directories are refreshed immediately.

## Module discovery

`MODULE_DIR` defaults to `REXX:AmBot/Modules`. AmBot discovers `.rexx` files into a fixed registry of at most 16 modules. Additional entries are skipped and counted.

Each module has a bounded 63-character state field reserved for later module APIs. No unbounded per-module allocation is introduced.

## Qualification boundary

M6 is implemented in source but still requires Bebbo cross-build and AmigaOS/FS-UAE runtime qualification. Runtime qualification should cover config parsing, auto-join, live `RELOAD`, module discovery limits, and M4/M5 ARexx regression behavior.
