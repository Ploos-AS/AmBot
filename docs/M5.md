# M5 — ARexx Event Automation

M5 connects the normalized M2 event stream to optional ARexx hook scripts.

## Hook location

AmBot looks for scripts in `REXX:AmBot/` using these fixed names:

- `ON_PRIVMSG.rexx`
- `ON_NOTICE.rexx`
- `ON_JOIN.rexx`
- `ON_PART.rexx`
- `ON_QUIT.rexx`
- `ON_KICK.rexx`
- `ON_TOPIC.rexx`
- `ON_NICK.rexx`
- `ON_CONNECT.rexx`
- `ON_DISCONNECT.rexx`

Missing scripts are ignored.

## Argument contract

Every hook receives four quoted arguments in this order:

`EVENT NICK TARGET TEXT`

For lifecycle hooks, `NICK` is the configured bot nick, `TARGET` is the IRC host, and `TEXT` contains the lifecycle reason such as `connected`, `requested`, `stopped` or `connection-lost`.

## Return contract

RC 0 means success. A non-zero RC is logged and increments the hook failure counter, but does not terminate the bot. Hook invocation and failure totals are printed when AmBot exits.

The hook runner communicates with RexxMast directly through `RexxMsg`. While waiting for a hook to finish, AmBot continues servicing its public `AMBOT` port, so a hook can use the M4 command API without deadlocking the event runner.

## Qualification boundary

M5 is implemented in source. It still requires Bebbo cross-build qualification plus runtime verification under AmigaOS/FS-UAE with RexxMast running and example hooks installed.

## Next milestone

M6 adds persistent configuration and module/script discovery so hook paths and behavior no longer need to rely only on the fixed M5 defaults.
