# M10 — PBMP / BotWeb integration

Status: **PLANNED**

M10 makes AmBot the third independent PBMP/1 bot implementation after LuCa and Engo while preserving the AmigaOS 2.04+/68000 baseline.

## Minimum profile

AmBot will implement `pbmp.info`, `capabilities.list`, `bot.info`, and `networks.list`. These methods are read-only and sufficient for BotWeb fleet discovery and status views.

## Architecture

The PBMP parser/serializer is a small bounded C module with no dependency on HTTP, JSON libraries, BotWeb, ARexx, or a specific transport. A separate Amiga adapter carries complete PBMP request/response records. ARexx remains the primary native automation interface.

The adapter must fit the existing event loop and bounded-memory model. The first implementation should prefer local or explicitly bridged management. Plain unauthenticated remote management is out of scope.

## Interoperability gate

A BotWeb instance must be able to register AmBot and obtain the same minimum PBMP/1 information it obtains from LuCa and Engo without implementation-specific BotWeb code.

## Non-goals

M10 does not embed a web server, browser UI, JavaScript runtime, or BotWeb backend in AmBot. It does not make PBMP mandatory for normal IRC or ARexx operation.
